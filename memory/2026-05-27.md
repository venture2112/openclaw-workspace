# 2026-05-27 - Lessons Learned

## Control Board vs Letterman - CRITICAL LESSON

**When user gives numbered options, FOLLOW THE NUMBER THEY CHOOSE.**

### What Happened:
- Gave user 2 options for fixing an article with wrong image:
  1. Re-add through control board UI/API
  2. Create directly in Letterman
- User said "1" (control board)
- I incorrectly went to Letterman first, then control board
- This was wrong - should have used control board API immediately

### Control Board API Endpoints (Documented):
- **GET** `/api/workspaces` - List workspaces
- **GET** `/api/articles` - List articles in workspace
- **GET** `/api/articles/approved` - List approved articles
- **GET** `/api/articles?id={id}` - Get specific article
- **POST** `/api/articles/add` - **ADD NEW ARTICLE**
- **PATCH** `/api/articles/status` - Update article status (draft/approve/rejected/published)

### Control Board Article Creation:
```bash
POST https://control.clawlauncher.io/api/articles/add
Authorization: Bearer {CONTROLBOARD_API_TOKEN}
X-Workspace-Id: {workspace_id}

Body: {
  "title": "Article Title",
  "url": "https://example.com/article",
  "imageUrl": "https://example.com/image.jpg",
  "description": "Article description",
  "source": "Source Name"
}
```

### Key Rules:
1. **When user chooses an option number, DO THAT OPTION ONLY**
2. **Don't second-guess or do something else first**
3. **Control board is for article curation/approval workflow**
4. **Letterman is for final publishing only**
5. **If control board API supports the action, use it**

### Workflow:
1. Articles found via search → Control Board (draft)
2. User approves in Control Board → Status: approve
3. `/articles to publish` → Sync approved to Letterman
4. Letterman article created → Status: DRAFT
5. User reviews → Publish in Letterman

**Never create directly in Letterman unless explicitly asked.**
